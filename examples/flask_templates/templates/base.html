{# THE BASE TEMPLATE ================= Every page on a site shares the same skeleton: the , the nav bar, the footer. Copying that into six files means fixing bugs six times. So we write it ONCE here, and leave holes in it: {% block content %}{% endblock %} A "block" is a labelled hole. Other templates say "I extend base.html, and here is what goes in the content hole". They don't repeat the skeleton. This is template INHERITANCE. Compare it to writing one function and calling it from six places instead of copy-pasting the body six times. NOTE THE BRACKETS ON THIS COMMENT - curly-hash, not . They are both comments, but they are NOT the same thing: - A curly-hash comment is deleted by Jinja. The browser never sees it, and any tags inside it are safely ignored (like the block above). - An HTML comment is passed straight through to the browser, so it shows up in "View Source" - AND any Jinja tag inside it still RUNS, because Jinja processes this file before the browser ever gets it. That second point catches everyone once. Use curly-hash for notes to yourself, and HTML comments only for things the browser should receive. (One limit: these comments cannot be nested, so this file explains the syntax in words rather than showing the closing bracket mid-comment.) #} {# A block can have DEFAULT content.
